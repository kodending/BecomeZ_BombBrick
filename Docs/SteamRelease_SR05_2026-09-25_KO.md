# SR-05 안전한 새 게임·데이터 초기화

2026-09-25. [Steam 출시 준비 과제표](https://docs.google.com/spreadsheets/d/YOUR_SPREADSHEET_ID/edit#gid=1950270647)

## 사용 방법과 범위

- **메인 화면 → 설정 → 데이터 → 새 게임 준비**에서 시작한다. 다른 게임 화면에서는 초기화를 실행할 수 없다.
- 몬스터 수집·편성, 증표·그물, 영구 연구, 지역·난이도 해금, 원정·결과 기록, 튜토리얼 진행을 초기화한다고 먼저 안내한다. 화면·음량·언어 설정은 유지한다.
- 확인창에 대문자 **RESET**을 입력해야 `백업 후 새 게임` 버튼이 활성화된다. 취소/ESC는 입력을 비우고 닫는다. 저장 실패 처리 중이나 장면 전환 중에는 시작할 수 없다.
- 완료 후 `튜토리얼 시작`을 누르면 새 기록으로 마을에 진입한다. 완료창을 닫고 나중에 메인의 `모험 시작`으로 들어가도 같은 새 기록을 사용한다.
- 최초 프로필과 동일하게 스타터 8마리, 비어 있는 원정 편성, 첫 마을 안내 0단계 및 포획 안내 0단계로 준비한다. 기본 지급품은 기존 최초 생성 규칙을 따른다.

## 저장과 복구

`PlayerProgressReset`은 개별 파일을 지우는 대신 새 프로필을 별도 폴더에 준비하고, 기존 `Profiles` 폴더 전체를 `Profiles.backups/<고유 ID>/Previous`로 옮긴 뒤 새 폴더를 활성화한다. 이전 프로필의 자동 백업, 원정 자동 백업, 임시 파일, 과거 보관 자료까지 한 폴더로 함께 보관한다. 새 프로필의 주 파일과 자동 백업은 모두 새 게임 기록이므로 오래된 원정이 되살아나지 않는다.

- 준비/백업에 실패하면 기존 기록을 유지한다. 재시도하려면 다시 RESET을 입력한다.
- `Profiles.reset`에 작업 ID를 기록하고, 다음 프로필 로드 전에 중단된 교체를 확인한다. 새 폴더가 활성화되기 전 중단됐으면 이전 폴더를 복원한다. 활성화된 후 중단됐으면 새 게임과 이전 백업을 유지한다.
- 잘못된 작업 ID, 충돌하는 폴더, 누락된 복구 폴더는 추측해서 덮어쓰지 않고 로드를 중단한다. SR-01/02의 로드 실패 보호와 함께 동작한다.
- 새 기록 활성화 이후 작업 표시 파일만 잠겼다면 다음 로드에서 정리를 재시도한다. 잠금이 풀리기 전에는 추가 초기화를 거부한다.
- 런타임 원정 세션은 새 저장이 준비된 다음에 교체한다. PlayerPrefs는 초기화하지 않는다.

현재 Windows 복구 백업 위치:

`%USERPROFILE%/AppData/LocalLow/DefaultCompany/BecomeZ_BombBrick/Profiles.backups/`

설정과 완료창에서 백업 폴더를 열 수 있다. 각 백업의 `RESTORE.txt`에 한·영 복구 방법과 실제 저장 경로를 기록한다. 복구 시 게임을 완전히 종료하고, 현재 `Profiles` 및 `Profiles.reset`/`Profiles.reset.tmp`가 있으면 따로 보관한 뒤 **Previous 폴더 전체를 Profiles로 복사**한다. 기존 폴더에 파일을 섞어서 덮어쓰지 않는다. 게임 안에서 과거 백업을 고르는 복구 UI는 이번 범위에 포함하지 않았다.

## 검증 결과

- EditMode 관련 **78/78 통과**: PlayerProgressResetTests, PlayerProfileRecoveryTests, ExpeditionSaveRetryTests, GameFrontendTests, GameHelpTests, ProductionExpeditionFlowTests.
- 초기화 검사는 실제 사용자 저장소와 분리한 임시 저장소에서 실행했다. 전체 파일 바이트 보존, 백업 실패, 교체 전/후 중단 복구, 잠긴 작업 파일, 반복 초기화, 잘못된 작업 ID와 폴더 충돌을 확인했다. 새 주 파일이 손상되어도 새 게임 자동 백업으로만 복구된다.
- 번역 DB 키·영어 완전성 검사 **1/1 통과**. 새 한·영 17문구를 로컬 DB와 `Localization_Master!A1607:I1623`에 반영하고 153셀 모두 재조회하여 일치 확인. 기존 셀 형식, Approved 목록, 체크박스를 보존했다. Google 시트는 API의 줄바꿈·정렬·검증 규칙 및 해당 행 자동 높이를 확인했다.
- PlayMode Boot에서 한국어 1920×1080, 영어 1366×768 확인창·완료창 배치를 확인했다. RESET 입력 전후 활성화, 취소 시 입력 삭제, 소문자 reset 거부, 하위 입력 차단 확인. 완료창은 표시 상태만 모의 설정했으며 실제 초기화를 호출하지 않았다.
- 실제 프로필·원정·보관 파일 **8개 전부 SHA-256 동일**, 파일 개수도 동일. 기존 플레이 기록은 초기화하지 않았다. 첫 튜토리얼 데이터는 임시 저장소와 기존 진행 테스트로 확인했으며 실제 사용자 기록으로 초기화→튜토리얼 전체 플레이를 수행하지는 않았다.
- 콘솔 오류 0. Boot 정지 상태, 한국어 및 Game View 1920×1080으로 복귀. 이번 변경의 별도 Windows 실행 파일 빌드는 수행하지 않았다.
